# release_notes/

App Store Connect / Play Console에 **그대로 복붙**해서 올리는 사용자 공지 문구를 여기에 둔다.
개발자 관점의 상세 이력은 루트 [`CHANGELOG.md`](../CHANGELOG.md)가 담당한다.

## 파일 네이밍

```
release_notes/
├─ 1.20.2.ko.txt          # 한국어 (Play Store / App Store KR)
├─ 1.20.2.en.txt          # (선택) 영어 — 글로벌 출시 시에만
└─ 1.21.0.ko.txt
```

- 파일명은 **버전 그대로**. 태그에 붙는 `-dev` / `-prod` / `-patch*` 같은 suffix는 쓰지 않는다.
  스토어에 올라가는 건 언제나 prod 정식 릴리즈 하나뿐이니까.
- 확장자는 `.txt`. 마크다운 강조는 스토어에 렌더링되지 않는다. 평문으로만.

## 포맷 규칙 (바이트픽 스타일)

- 상단 제목 줄은 넣지 않는다 (스토어 UI가 버전을 자동 표기).
- 섹션 태그는 `[신규 기능]`, `[버그 수정]`, `[기타]` 셋을 기본으로 쓴다.
- 각 항목은 `- ` 로 시작하고, **"~해요" 체**로 부드럽게. 기술용어 노출 최소화.
- 사장님 전용 기능이면 `- (사장님)` prefix를 붙여 구분.
- Play Store 현지화 릴리즈 노트는 500자 제한이 있으니 총 길이에 유의.

### 예시

```
[신규 기능]
- 오픈 알림 신청을 취소할 수 있어요
- 푸시 알림을 탭하면 관련 페이지로 바로 이동해요
- 예약 가능한 상품을 필터 칩으로 빠르게 확인할 수 있어요

[버그 수정]
- 픽업 시간 선택 오류를 수정했어요
- 페이징 오류를 수정하고 무한 스크롤을 추가했어요
- 리뷰 사진 표시 방식을 개선했어요
- 네트워크 차단 시 에러 화면 노출 방식을 개선했어요
- 사장님 계정의 안정성 문제를 수정했어요
```

## 작성 플로우

1. `./scripts/release.sh {bump}` 를 돌리면 `release_notes/{new_version}.ko.txt` 스켈레톤이 자동 생성된다.
   - 스켈레톤은 같은 릴리즈의 `CHANGELOG.md` 항목들을 기반으로 뽑아놓은 초안이다.
2. 스토어 톤(`~해요` 체, 유저 친화 어휘)으로 **손으로 다듬는다**. 기술적 세부사항은 제거.
3. 다듬은 뒤 커밋 — 릴리즈 태그 push 전에 포함되도록.
4. Play Console / App Store Connect의 **현지화 릴리즈 노트(한국어)** 필드에 파일 내용을 그대로 붙여 넣는다.

## 체크 포인트

- [ ] 500자 이하 (Play Store 제한)
- [ ] 내부 용어(ex. "DTO", "엔드포인트", "토픽", "페이로드") 제거
- [ ] 사장님 / 손님 중 하나에만 해당되는 변경은 그 대상을 명시
- [ ] 버그 수정 항목은 "~했어요" / "~수정했어요" 로 끝나게
